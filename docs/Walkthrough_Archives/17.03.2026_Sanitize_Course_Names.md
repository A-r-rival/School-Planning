# Walkthrough: Course Name Sanitization & DB Synchronization

**Date:** March 17, 2026  
**Goal:** Unify and clean course names across the curriculum so that identically named courses (but in different languages or with Roman numerals) are treated correctly as the same single course object.

---

## 1. Context and Problem
The `curriculum_data.py` file initially contained raw names scraped from curriculum PDFs. As a result, many courses existed in a "dual language" format (e.g., `Analiz I / Analysis I`, `Akışkanlar Mekaniği / Fluid Mechanics`). Moreover, some courses were designated with Roman Numerals (e.g., `Analiz I`), while humans and other programs expect standard decimal digits (`Analiz 1`). This disparity led to the database identifying the same logical course as two distinct entries if the naming varied slightly.

## 2. Solution: `sanitize_course_names.py`
To solve the issue, a dedicated Python script `scripts/sanitize_course_names.py` was developed. 
It performs the following:
1. **Language Heuristics:** Splits "slash-separated" dual names and evaluates which side is more likely to be Turkish by checking for Turkish-specific characters (`ç, ğ, ı, vb.`) and common keywords (`ve, giriş, müh, sistem`). The side with the higher "Turkish Score" is selected.
2. **Roman Numeral Conversion:** Detects distinct Roman numeral words (I, II, III... X) using Regex and converts them to Arabic numerals (1, 2, 3...). 
3. **Data Source Modification:** The script modifies `database/curriculum_data.py` directly by executing a safe string literal replacement on the Python content. An indicator `# Sanitized by the script` is placed at the top of the file to confirm execution.
4. **Relational Database Synchronization:** Since existing deployments already contain the multi-language names in the `okul_veritabani.db` SQLite database, merely fixing `curriculum_data.py` is not enough. The script updates the actual `Dersler` table, mapping old names to the new cleaner forms securely.
5. **Cascading Relational Updates:** In solving bugs where courses disappeared from the UI, we discovered `Ders_Sinif_Iliskisi`, `Ders_Havuz_Iliskisi`, `Ders_Programi`, `Ders_Ogretmen_Iliskisi`, and `Ogretmen_Ders_Tercihleri` tables held references to the old string names. The script also iterates through these tables to ensure relational integrity is preserved after a rename. In the event of an `IntegrityError` (a unified name creating duplicates in relational mappings), the script correctly removes the duplicate safely.

## 3. UI Integration
A button labeled **"Müfredat İsimlerini Temizle"** was seamlessly added to the top filter header of the `CurriculumViewDialog` (`views/curriculum_view.py`).

**Workflow:**
- The user hits the button.
- A confirmation dialog warns that `curriculum_data.py` and the database will be modified.
- The UI spawns a subprocess running `scripts/sanitize_course_names.py`.
- If successful, a success dialog notifies the user, and they can restart/refresh the table to see perfectly unified and clean names (e.g. `Analiz 1`).

## 4. Maintenance / Cleanup
Several temporary scripts used precisely for debugging regex strings (`dump_names_with_slash.py`, `heuristic_test.py`, `verify_analiz_courses.py`) were purged during implementation to keep the codebase clean. `sanitize_course_names.py` remains in the `/scripts` directory as a permanent utility tool.
