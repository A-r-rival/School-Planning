# Walkthrough: 30-Minute Time Slot Normalization & Lunch Constraint (18.02.2026)

## Overview
This major refactor normalizes the entire scheduling system from 1-hour blocks to **30-minute intervals**. This granularity was required to implement a mandatory **Lunch Break Constraint** (11:30 - 14:00) where students must have at least 30 minutes of free time.

## 1. Core Changes

### Time Slot Refactoring
- **New Grid**: The day now consists of **18 slots** of 30 minutes each.
- **Start Time**: 08:30
- **End Time**: 17:30
- **File**: `controllers/scheduler.py`
  - `self.slots_per_day = 18`
  - `start_time_string` and `end_time_string` keys added for clarity.

### Course Duration scaling
- Since slots are now 30 minutes, all existing course durations (Teori, Uygulama, Lab) have been multiplied by **2**.
- **1 Class Hour = 2 Slots**.
- **File**: `controllers/scheduler_services.py`

## 2. Lunch Break Constraint
- **Goal**: Ensure every student group has at least one empty 30-min slot between **11:30 and 14:00**.
- **Implementation**:
  - Identified slots falling within the lunch window (Indices 6-10).
  - Applied a hard constraint: `Sum(Occupied Slots in Window) <= (Total Window Slots - 1)`.
  - This guarantees at least 1 slot remains `0` (empty).
- **File**: `controllers/scheduler.py` -> `add_lunch_break_constraints()`

## 3. UI Updates

### Master Schedule View
- **Path**: `views/master_schedule_view.py`
- Refactored to generate columns based on the new 18-slot grid.
- **Cell Merging**: Implemented a "span" logic to merge contiguous slots for the same course. This prevents "MAT101 (G1)" from appearing twice for a 2-slot course; it now appears as a single wide cell.

### Calendar View
- **Path**: `views/calendar_view.py`
- Updated parsing logic to handle `08:30` start times and 30-minute increments.
- Rows are now generated for every 30-minute interval.

## 4. Verification
A dedicated verification script was created to test the constraint logic specifically.
- **Script**: `tests/verify_lunch_constraint.py`
- **Results**:
  - **Pass**: Scheduling a course that leaves a gap in lunch window.
  - **Fail**: Attempting to schedule a course that consumes the entire 11:30-14:00 block (Correctly identified as `INFEASIBLE`).

## 5. Debugging
- Verbose debug logs (`DEBUG_CONST`, `DEBUG_LUNCH`) were added during development but have been **commented out** for production to reduce console noise.
